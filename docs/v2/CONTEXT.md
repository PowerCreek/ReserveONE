# v2 accumulated context (read first; the lead amends in place)
- Direction: the sim is a free-play host sandbox; guests react naturally (mood, patience, leaving, accepting or declining offers) and the event log shows what happened; no rubric, grades, scoring or expected outcomes; a scenario is only a starter setup.
- Domain truth: `docs/SPEC.md` (§ refs), v1 code in `src/` (read-only reference), v1 decisions in `docs/HANDOFF.md`.
- v2 lives in `v2/`; branch `v2/engine-sim`; v1 stays untouched until parity.
- Build target: one self-contained `dist/index.html`; tests run with node (no browser).
- Stack: TypeScript, esbuild, Tailwind CLI (compiled at build), vanilla DOM + Proxy/MutationObserver (no React).
- Contracts + lanes: `docs/v2/ARCH.md` (frozen; changes via lead). Output file: `dist/v2.html`.
- Node 24 runs `.ts` directly: use `.ts` import extensions, `import type`, no enums/namespaces.
- Commands: `npm run v2:check|v2:test|v2:build`; lane tests `node --test "v2/<lane>/**/*.test.ts"`.
- Lanes do not commit; the lead commits after review. Tailwind `--watch` is untested; one-shot build is the loop.
- Kernel binders (lane B, done): `data-text`, `data-class`, `data-attr="path" data-as="attr"`, `data-show`, `data-each="path"` with a child `<template>` (`$`/`$.x` = row path; `data-has="table,pos"` filters by components), `data-on="input:act change:act2"`/`data-act`, `keyOf(ev)` = row key. Undo/redo: `record`, `commit`, acts `undo`/`redo`, state in `state.ui.history`. `persist(key?)` plugin. Kernel exports also: `runRules`, `matches`, `make`.
- Engine/sim conventions (lane A): an entity id `door` with a `pos` is the spawn point; a guest's `body.party` is its own id and its `serve` task means "awaiting service"; `ents[key].id === key` always; new party number = max(party.num)+1; a leaving guest = `del` + `add` of the stripped entity. Engine extras exported: `apply`, `queueOrder`, `line`, `freeUp`, `eventState`, `sectionStats`.
- UI (lane C): panels read the engine through an optional-call helper; sim presets live in `v2/ui/presets.ts`; geometry in `v2/ui/geo.ts`.
- Policy (lane D, promoted from the old engine knobs, which is deleted): `look {probes,tight,sizes,msg}`, `rows {past,future}`, `section {minOcc,share,horizonMin}`, `spawn {names,sizes}`, `sim.door [x,y]` (24,260), `sim.floor [w,h]` (800,520). `sectionStats` now takes the policy first: `sectionStats(p, w, now, s)`.
- Door agreement: the engine spawns guests at the `door` entity's `pos`; `ui/geo.ts` (W, H, DOOR) and `ui/presets.ts` `layout` both read `defaultPolicy.sim`, and `main.ts` seeds `door` from it. Any world without a `door` entity spawns guests at (0,0).
- `main.ts` seeds the real venue from `v2/venue.ts` (4 floors, 66 tables, ids `rf_*`, unsectioned, v1 flow scaled onto `sim.floor`) plus `door`; no staff, so the sim idles until a preset loads. `persist` is not wired in (add `.use(persist())` before `ui` to opt in).
- Headless preset run: `v2/test/real.ts` -> `real()` mounts real engine+ui in jsdom; `run(app, 'rush', 120)` loads a preset and steps the clock 120 x 1 s, returning every `SimEvent`. Turns last 45-90 sim minutes, so `cleared`/`left` need ~100+ sim minutes; set `ui.rate = 0` first when stepping that far (a long queue makes the jsdom repaint slow).
- `v2/test/boot.test.ts` runs `v2/build.mjs` itself and boots `dist/v2.html` in jsdom.
- Open (from lane D): engine `center('door')` should fall back to the policy door; floor view ignores `floor` (4 floors overlap: add a floor selector in `v2/ui/floor.ts`); clean-slate seed has no host/servers/sections so the sim idles until a preset loads.
- v1 parity not yet in v2: Gantt, audit log, ledger, locator, sections-as-blobs editing, layout mode/editing, shifts, drawer widgets, book wizard.
- Convention (pinned): a party is "led, not seated" when it has an `offer` with `status: 'accepted'` on a table and no `slot` on that table; "seated" = has the slot. Stage for requests: arrived | seated accordingly.
- Starters: `ui/scenario.ts` `load(app,id)` loads presets or `scenarios[id]`; `choices()` lists both; `controls.ts` picker must render `choices()` (U4).
- Match (E1): a want counts only once `said` or in `heard` (the host asks, then records); "elsewhere" = another floor or section than the best-scoring spot; `heard` events derive from the intake patch in E0 (Decision carries no events).
- Respond (E2): `askedEvent(w,party)` builds the `asked` event; `settle(p,w,now)` is the pure tick helper returning `{patches,events}` (lapsed offers -> `answered` no, ignored requests decline, patience exhausted -> `left`). E0 must call both; U1 'place' writes an accepted offer. Decision: `refuse` is a host option on every reason (add to policy.host.options).
- Service modes (wave 3): `contracts/service.ts` + DOMAIN "service modes". Day mode = `policy.service.schedule` unless the `service` entity overrides; table area = `area` component (grotto shares floor rf1 with main); holds = `table.section` (chunks/whole), `assign` (tops), `staff.area` (bartender pair, `weight` 2); awareness = `policy.service.areas[id].seen`, else the host `tell`s and `slot.told` is set. `policy.sim.autoSeat` (default false): the sim host does not seat until the player acts.
- Binder names reserved in views (do not reuse for ids): `data-staff` and the kernel `data-*` set; carry ids in `data-who`/`data-tid`. Active-slice rule: UI must call the engine's `modeAt`, never recompute from local time (U5 `assign.ts` recomputes it today: replace with the engine call).
- Venue layout (owner images, gist 0b87189204ca9e6ccc15d86e62c8f57c): `venue.ts` `placed` holds centres in image px (aligned rows/columns: quads 5-8 and 13-16 share y; bottom row 17-24 one y), one uniform scale S into policy floor px; adjacency = side-by-side (axis overlap) within `policy.merge.gapPx`. Grotto G1-G6 are 4-top chairs; bar B1-B12 stools (cap 1), B14/B16/B20 corner 3-tops, B15 2-top, B21 4-top, B22 blocked (managers' desk). Upstairs has no image yet (reading-order flow).
- Sections (E1): `engine/partition.ts` `partition(policy, tables, k)` is the one allocator (recursive bisection into quadrant blocks); `crew.ts` calls it at seed time. Floor tints and chips: only `seat`-group chips show on the layout (rest in tooltips); section tints are per table.
- Stand shows the server recorded on the table (`table.waiter`) for seated parties, who would serve each offer, and the rotation order in rotation mode. Bar is a `seen` area (bartenders see seatings).
- Merging (E1): `venue.ts` RUNS/ACROSS/CENTRE are the only adjacency data (no geometry inference); `engine/merge.ts` enumerates connected sets up to `policy.merge.max`; `engine/keep.ts` `keeper` answers which due, table-less reservations a seating would strand (used by fit and match, surfaced as `Fit.squeezes` / `Rung.squeezes` and the ladder's warning). `merges(p, w)` and `spotOf(p, w, id)` now take the policy. Quads, booths and 23-24 no longer merge (not in the owner's list); to add a run, add it to RUNS.
- Self-seat: `policy.seat.selfSeat` shape list (stools); `seatcheck.refuse(p, ...)` refuses them; floor tab counts skip them.
- Temporal plan (E1): `engine/plan.ts` `planner/outlook` is the one place that reasons about the future (table free times via `avail.tableFreeAt`, link-expanded; reservation windows via `reserved.ts`, split from the standing holds in `holds.ts` to avoid an import cycle with `rotate.ts`). `keep.ts`, `rotate.ts` (planned covers, `skip` = the party being seated) and `section.ts` read it; `fit.ts` also quotes merges of tables still turning over.
- UI calls to action (`ui/tone.ts`): `cta` (one next step), `ctaSm`, `ok`, `ghost`, `choice(picked)`; radio groups use role=radio + aria-checked; the stand shows one thing to do at a time (an open offer hides the ladder list).
- Desk seam (wave 4, landed): `contracts/desk.ts`. Writes = `engine.act(p,w,now,cmd)` (`engine/act.ts`, one row per `Cmd`) -> `Outcome {patches, events, msg, tone, says?}`; UI dispatches through `ui/act.ts` `run(app, cmd)` (commit, narrate events, log `msg` only when no event narrates it or it warns). The stand renders `engine.stand(p,w,now,focus)` (`engine/desk.ts`) -> `StandView`; the queue's waiting list reads its door rows. Seat = one click (`seat` records the accepted offer and seats; a sim host carrying that party drops the trip); `decline` appends to `offer.declined` and the ladder never proposes those spots again. Policy is a provided service: `ask` binds `app.services.policy`, views read `policyOf(app)`; `draw.ts`/`geo.ts`/presets keep `defaultPolicy` as layout constants. Engine party ids from `act` are `pty<n>`, labels `W-<n>`.
